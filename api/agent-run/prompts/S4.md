# S4 — Token enrollments, BIN metadata, and hosted authentication

Reuse `card_enrollments` as the payment-method record. Accept provider-issued
references only; do not create a PAN/CVV card API. BIN lookup accepts exactly
six digits and returns allowlisted public metadata only.

The payment UI may continue a provider-hosted 3DS/OTP action for an explicit
tokenized sale or preauthorization. Store transaction references and status,
never authentication secrets. Do not run auth-only checks to classify a card,
create a `live/dead` result, or add failure-count burn behavior. Include safe
request examples for BIN metadata and tokenized enrollment.
