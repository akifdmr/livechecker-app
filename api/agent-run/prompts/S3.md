# S3 — Provider registry and safe results

Reuse `api/core/ProviderFactory.js` and existing Stripe, Clover, Moneris, and
other provider adapters. Do not add a mock provider or another credentials
store. Only expose providers that support the existing tokenized POS flow.
Users use the server-configured default provider; admins can set that default
or select a provider for an explicit operation.

Provider responses must be allowlisted before persistence or return. Never
persist raw response bodies, PAN/CVV, client secrets, OTP values, or payment
tokens. Support only provider-issued hosted authentication redirects returned
for an explicit tokenized payment; do not build an auth-only card verification
flow. Missing credentials must fail closed.

Completion format: DONE, paths, existing adapters reused, commands and whether
executed, remaining provider configuration requirements.
